# Data Model: Cadastro de Serviços

## Entity: Serviço (`Service`)

Represents a service offered by the barbershop.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| id | UUID / BIGINT (auto-generated) | PK, not null | Unique identifier generated by the system |
| name | VARCHAR(255) | Not null, trimmed, unique among active services after normalization | Service name displayed to users |
| description | VARCHAR(1000) | Optional, nullable | Optional service description |
| durationMinutes | INTEGER | Not null, > 0 | Estimated duration in minutes |
| price | NUMERIC(10,2) | Not null, >= 0 | Price in Brazilian Reais (BRL) |
| active | BOOLEAN | Not null, default true | Indicates if the service is active |
| createdAt | TIMESTAMP | Not null, auto-generated | Record creation timestamp |
| updatedAt | TIMESTAMP | Not null, auto-updated | Last update timestamp |

## Validation Rules

- `name` is mandatory and cannot be blank after trimming.
- `name` uniqueness is checked among active services using normalized comparison (case-insensitive, accents ignored, leading/trailing whitespace removed).
- `durationMinutes` must be greater than zero.
- `price` must be zero or positive, with at most two decimal places.

## State Transitions

```
[CRIADO] --(ativo=true)--> [ATIVO]
[ATIVO]  --(desativar)--> [INATIVO]
[INATIVO] --(ativar, sem conflito de nome)--> [ATIVO]
```

- Activation of an inactive service is rejected if another active service already has the same normalized name.
- Activation/deactivation is idempotent.

## Relationships

- No direct relationships with other entities in this feature.
- Future scheduling features will reference `Service` by its `id` and filter only `active = true` records.

## Database Schema (Flyway Migration)

```sql
CREATE TABLE services (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    description VARCHAR(1000),
    duration_minutes INTEGER NOT NULL,
    price NUMERIC(10,2) NOT NULL,
    active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_services_active ON services(active);
```

> Note: A unique constraint on normalized name among active services cannot be expressed directly in DDL because normalization is application-level. The application layer must enforce this rule.
